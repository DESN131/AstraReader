全部通过逐页可见内容对比：

| 指标 | 结果 |
| --- | ---: |
| EPUB 图书 | 3 |
| spine 项 | 91 |
| 分页状态 | 1,949 |
| 规范化正文 | 364,010 字符 |
| 图片元素 | 84 |
| 可见页拼接与章节原文不一致 | 0 |
| 缺失、重复或额外正文 | 0 |

本次审计覆盖的是用户逐页实际能看到的文本，而不是只比较 iframe 内完整
`body.textContent`。旧实现虽然 DOM 完整，但仍可能因分页步长、相邻列露出或
错误的全 DOM 分栏校验而让用户看到缺页或错误提示；因此该比较方法已被替换。

## 审计环境

- 浏览器：隔离 Playwright Chromium 会话，不操作使用者当前浏览器。
- 视口：`1271 × 634` CSS 像素。
- 排版：`20px` 字号、`1.8` 行距、`0.8em` 段距、`640px` 版心、两端对齐。
- 主题：VS Code 深灰。
- 模式：单列分页。
- 阅读引擎：Foliate.js 1.0.1。

移动端 `390 × 844` 还检查了 EPUB 正文左/右边界、末页、滚动进度滑块和模式
切换；生产构建在独立端口复验过打开、定位和正文渲染。

## EPUB 方法

1. 按 Foliate 的 `book.sections` 顺序遍历全部 spine 项。
2. 每节从 `anchor: 0` 开始。
3. 读取当前分页器给出的可见 `Range`：

   ```javascript
   view.lastLocation.range.toString()
   ```

4. 调用真实翻页逻辑，记录该节每一页的可见 Range，直到 section index 改变。
5. 去掉换行和空白后，拼接所有页的 Range 文本。
6. 与当前 section 文档的 `body.textContent` 同样规范化后逐字符比较。
7. 记录每个 section 的分页数、原文长度、可见文本长度、首个差异位置和图片数。

核心不变量：

```text
normalize(page_1.range + page_2.range + ... + page_n.range)
  === normalize(section.body.textContent)
```

这个比较能发现以下问题：

- 某页只渲染了 DOM，但实际被裁到视口外。
- `next` 跳过了某个可见 Range。
- 相邻分页范围重叠，导致同一段重复出现。
- 章节末尾没有进入最后一页。
- 分页步长与页宽不一致后，错误 Range 被当成下一页。

## 设置与模式检查

除全量分页审计外，还验证：

- `20px / 1.8 / 0.8em / 640px` 在分页模式正常。
- `25px / 2.2 / 1.2em / 980px` 主题和行距规则实时生效。
- 分页切到上下滚动时保留同一 section 和可见 Range。
- 上下滚动使用不占正文宽度的右侧悬浮进度滑块。
- 修改字号、行距和版心后仍停留在原章节位置。
- 左右方向键在分页模式下只移动一页，不跨章节。
- 卷 15 历史 100% 进度打开时落在真正的最后分页或滚动末尾。
- 移动端纸张不会横向溢出，正文不会被左右边框裁切。

## 复现要点

自动化工具使用 `@playwright/cli` 的隔离会话。审计时不要复用使用者当前 Chrome：

```powershell
npx --yes --package @playwright/cli playwright-cli -s=astra-audit open http://127.0.0.1:3000
```

在阅读页执行逐节、逐页的 Range 拼接比较。审计完成后恢复正式数据库中的阅读
进度、最近打开时间和阅读统计，不要用审计图书覆盖个人书库。

## 边界说明

- 比较对象是 EPUB spine 文档中的可见文本、图片元素和分页顺序。
- 不包含 DRM、远程资源、书内脚本和受 CSP/sandbox 主动阻止的内容。
- CSS 背景图、字体字形差异和复杂固定尺寸浮动仍可能受浏览器多栏实现限制。
- 复杂书籍的“视觉样式一致”不等于“正文完整”；本审计保证的是正文和本地图片
  不丢失、不重复、不跨页跳过。

# EPUB 内容完整性审计

## 审计范围

本次审计选择新导入、包含 26 个书脊项的 EPUB 副本，使用隔离 Playwright
浏览器从封面连续翻到全书结束。审计只读取原始书籍文件；测试写入的阅读进度
和阅读时长在结束后已清理，不修改用户书籍文件。

审计目标：

- 按 OPF `spine` 顺序提取 EPUB 原始章节内容。
- 按 EPUB.js 实际渲染顺序逐节读取阅读器正文。
- 对比全部正文、图片元素数量和每节页数。
- 逐字符检查文本和图片是否越过实际内容栏边界。
- 检查页步长、连续翻页顺序和全书结束位置。

## 方法

原始内容提取：

1. 在浏览器中解包 EPUB 的 `META-INF/container.xml` 和 OPF。
2. 按 `itemref` 顺序读取每个 spine 文档。
3. 移除 `script`、`style`、`noscript`、`template`。
4. 对正文执行 NFKC 规范化和空白移除，保留所有非空白字符。
5. 统计每个 spine 项的 `img`、SVG `image` 和 `image` 元素数量。

渲染内容提取：

1. 从 EPUB 书脊第一项封面开始，通过阅读器真实“下一页”操作逐页读取。
2. 从 EPUB.js iframe 的 `body.textContent` 中执行相同的规范化。
3. 读取每个章节的图片元素数量，并核对 OPF `spine` 路径。
4. 核对每节实际页数与 `scrollWidth / clientWidth`。
5. 检查实际列宽是否为视口宽度减 32px、页步长是否等于视口宽度。
6. 对每个非空白字符和图片计算布局矩形，确认没有越过所属内容栏。

规范化只忽略空白差异，不忽略文字、标点、数字或章节顺序。

本次审计结果：

| 指标 | 结果 |
| --- | ---: |
| spine 项 | 26 |
| 有文本的 spine 项 | 20 |
| 规范化正文字符 | 125,485 |
| 图片元素 | 19 |
| 实际翻页数 | 409 |
| 书脊项访问顺序 | 26 / 26 |
| 文本和图片一致 | 26 / 26 |
| 每节页数一致 | 26 / 26 |
| 分页步长一致 | 26 / 26 |
| 字符与图片栏边界 | 26 / 26 |
| 缺失或额外文本 | 0 |

审计还确认：

- 新书没有历史进度时，书脊第一项为封面，阅读器显示封面且进度为 0%。
- 默认审计视口为 `694px`，实际内容栏为 `662px`，栏间距为 `32px`，
  页步长等于 `694px`。
- 26 个书脊项均按 OPF 顺序出现，没有跳过或额外插入的章节。
- 全书 409 页均可通过真实“下一页”操作到达；最后一节完整显示 7 页。
- 没有发现重复页、左侧邻页混入、右侧文字裁切或跨栏字符。
- 审计结束位置为最后一节最后一页，阅读进度为 100%。

## 边界说明

本审计比较的是 EPUB 正文 DOM 与阅读器实际渲染 DOM 的规范化文本、图片元素
数量和布局边界，不是逐像素图像比对；CSS 背景图、字体字形细节和受 DRM
保护的资源不在比较范围内。对于文字章节，规范化后逐字符一致；对于图片章节，
图片元素数量和所属内容栏边界一致。
